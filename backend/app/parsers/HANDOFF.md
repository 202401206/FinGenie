## 1. Quick Integration Summary

The parser is completely pure: it has **no dependencies** on FastAPI, Supabase, HTTP sessions, or LLMs. It takes raw file bytes and returns a validated Pydantic model (`BankStatement`) or raises safe, typed parser exceptions.

### Import:
```python
from app.parsers.bank_statement import parse_bank_statement
from app.parsers.errors import (
    AmbiguousWorksheetError,
    BankStatementParserError,
    InvalidStatementError,
    ResourceLimitError,
    UnsupportedFormatError,
)
from app.schemas.bank_statement import BankStatement, BankTransaction
```

### Signature:
```python
parse_bank_statement(content: bytes, *, file_kind: str, document_id: UUID) -> BankStatement
```
- `content`: Uploaded file bytes.
- `file_kind`: Either `"csv"` or `"xlsx"` (case-insensitive).
- `document_id`: The UUID generated by the backend for the upload context.

## 2. API Route Error Mapping (For Anshuman)

Parser exceptions inherit from `BankStatementParserError` and contain safe, sanitized error messages (no leaked raw customer cells or credentials). You can catch and map them directly to HTTP status codes:

| Parser Exception | Suggested HTTP Status | Reason |
| :--- | :--- | :--- |
| `UnsupportedFormatError` | **415** (or **422**) | File kind not supported, non-UTF8 encoding, corrupted XLSX, or unmapped table headers. |
| `ResourceLimitError` | **413** (or **422**) | File > 5 MiB, expanded XLSX > 25 MiB, > 10,000 transactions, or > 50 columns. |
| `AmbiguousWorksheetError` | **422** | XLSX contains multiple candidate sheets matching table headers. |
| `InvalidStatementError` | **422** | Missing required headers, malformed dates, non-numeric amounts, or formula in financial cells. |

### Example FastAPI Handler:
```python
try:
    statement = parse_bank_statement(file_bytes, file_kind=file_ext, document_id=doc_id)
except UnsupportedFormatError as exc:
    raise HTTPException(status_code=415, detail=exc.message)
except ResourceLimitError as exc:
    raise HTTPException(status_code=413, detail=exc.message)
except (InvalidStatementError, AmbiguousWorksheetError) as exc:
    raise HTTPException(status_code=422, detail=exc.message)
```

## 4. Supported Layouts Summary

1. **Layout 1 (Standard Retail / Demo):** Headers `Date`, `Description`, `Debit`, `Credit`, `Balance` with ISO `YYYY-MM-DD` dates.
2. **Layout 2 (Commercial Statement B):** Headers `Txn Date`, `Particulars`, `Withdrawal (Dr)`, `Deposit (Cr)`, `Net Balance` with delimited `DD/MM/YYYY` dates and support for extra columns like `Chq/Ref No`.
